# 哄哄 技术方案（三阶段）

> 所有判断结果仅供参考，不能替代医生。隐私默认：数据只在手机本地。

| | 第一阶段：本地规则版 | 第二阶段：攒数据 | 第三阶段：真模型 |
|---|---|---|---|
| 目标 | 上线即可用 | 收集带标注的哭声 | 提升猜中率 |
| 客户端 | Flutter + Riverpod + drift，YAMNet 端上检测哭声、自动开录 | 增加"参与改进"开关，Wi-Fi 下上传 | 加载 TFLite 分类模型，端上个性化 |
| 猜原因 | `RuleBasedPredictor`（上下文规则加权） | 同左 | `TfliteCryPredictor`（音频 embedding + 上下文） |
| 后端 | 无 | 自建 Supabase：Storage 存片段，Postgres 存事件/标注，匿名 ID | 同左 + 模型下发与灰度 |
| 训练 | 无 | 公开数据集预训练 | Python：YAMNet embedding + 上下文 → 小分类器 → TFLite |

关键设计：
- `CryPredictor` 接口：三个阶段只替换实现，界面和数据不动。
- `CryEvent` 表（录音 + 上下文 + 判断 + 反馈）就是训练数据。
- 上传只传裁剪后的哭声片段（16kHz 单声道，约 300KB/10 秒）。
- 核心指标：第一名与家长反馈一致率（top-1）。

## 服务器配置（第二阶段起）
- 推荐 4 核 8G，最低 2 核 4G；50–100G SSD；带宽 5M 起
- Ubuntu 22.04/24.04，Docker，Caddy/Nginx 配 HTTPS
- 只开放 80/443，数据库不暴露公网；每日备份数据库和录音到异地
- 训练不在服务器上做：本地 CPU 或按需租云 GPU；推理在手机端
- 国内服务器需 ICP 备案
